# Лабораторная работа №4

React-приложение, Spring Boot API и PostgreSQL запускаются вместе через Docker Compose.

## Запуск

1. Скопируйте `.env.example` в `.env` в каталоге `lab4`.
2. Задайте `DB_PASSWORD` и `JWT_SECRET`. `JWT_SECRET` — Base64 от случайных 32 байт. В PowerShell его можно создать командой:

   ```powershell
   [Convert]::ToBase64String([System.Security.Cryptography.RandomNumberGenerator]::GetBytes(32))
   ```

3. Для локального запуска по HTTP оставьте `COOKIE_SECURE=false` и пустой `CORS_ORIGINS`.
4. Выполните из каталога `lab4`:

   ```powershell
   docker compose up -d --build
   ```

Frontend: `http://127.0.0.1:8081`. Backend API: `http://127.0.0.1:8080`. Остановить контейнеры: `docker compose down`. Данные PostgreSQL сохраняются в томе; `docker compose down --volumes` удалит их.

## Авторизация в браузере

- `POST /api/auth/session/login` проверяет логин и пароль. Ответ содержит только короткоживущий access JWT. Он хранится в памяти React и отправляется с запросами к защищённым данным через заголовок `Authorization: Bearer ...`.
- Refresh-токен сервер отправляет в cookie `lab4_refresh` с `HttpOnly`, `SameSite=Strict` и ограниченным путём `/api/auth/session`. JavaScript не читает этот cookie. Сервер хранит только SHA-256 хеш refresh-токена и заменяет токен при обновлении.
- При перезагрузке страницы `POST /api/auth/session/refresh` восстанавливает access-токен из cookie. Если защищённый запрос получил 401, приложение обновляет токен и повторяет запрос один раз. Одновременные запросы используют одно обновление.
- `POST /api/auth/session/logout` отзывает refresh-токен, удаляет cookie и очищает access-токен в React.
- Ответы авторизации имеют `Cache-Control: no-store`. Для cookie-маршрутов требуется заголовок `X-Requested-With: XMLHttpRequest`; список разрешённых источников ограничен `CORS_ORIGINS`.

Старые маршруты `/api/auth/login`, `/api/auth/refresh` и `/api/auth/logout` сохранены для клиентов API лабораторной №3. Фронтенд использует только маршруты `/api/auth/session/*`.

Локальные порты в Compose доступны только через `127.0.0.1`. Для доступа извне настройте HTTPS на обратном прокси, установите `COOKIE_SECURE=true`, укажите точные HTTPS-адреса в `CORS_ORIGINS` и замените локальные привязки портов. Пароли и токены нельзя передавать по открытому внешнему HTTP.

## Разработка frontend

В каталоге `frontend` запустите `npm ci`, затем `npm run dev`. Vite перенаправляет `/api` на backend на порту 8080. Проверка кода: `npm run build`, `npm run lint` и `npm test`.

## Страницы и роли

Вкладки сверху переключают страницы без перезагрузки. После регистрации перейдите во «Вход», затем откройте «Студенты» или «Профиль».

- `/login`, `/register` — вход и регистрация.
- `/profile` — имя, почта, роль и выход из системы.
- `/students` — список, поиск по ФИО, фильтры по всем полям, сортировка и страницы по 10 записей.
- `/students/:isuId` — все сведения о студенте.
- `/students/new`, `/students/:isuId/edit` — создание и редактирование для ADMIN. Удаление находится на странице студента и требует подтверждения.

Обычная регистрация создаёт пользователя с ролью USER: он может просматривать студентов. Создание, изменение и удаление доступны ADMIN; backend проверяет права независимо от интерфейса. Учётная запись и запись студента — разные сущности, регистрация не добавляет студента автоматически.

Чтобы создать администратора, заполните в `.env` значения `ADMIN_USERNAME`, `ADMIN_EMAIL` и `ADMIN_PASSWORD`. Используйте отдельное имя, которое ещё не занято обычным пользователем. Пароль должен содержать 8–72 символа и занимать не более 72 байт UTF-8. Затем выполните:

```powershell
docker compose up -d --build backend frontend
```

Администратор создаётся при запуске backend. Если он уже существует, пароль не меняется. Войдите под ним: появятся вкладка «Создать студента» и кнопки изменения и удаления. Для запуска без создания администратора оставьте все три значения пустыми.

## RxJS и структура

`frontend/src/api/studentStream.js` обрабатывает поток параметров списка: задерживает запрос на 250 мс, пропускает повторы и отменяет предыдущий запрос через `switchMap` и `AbortController`. Hook `useStudentList` подписывается на поток и снимает подписку при уходе со страницы. Компоненты получают состояния загрузки, результата и ошибки.

`StudentForm` используется для создания и редактирования. При редактировании номер ИСУ остаётся неизменным. Access-токен и текущий пользователь находятся в общем `AuthContext`; обновление токена сохраняет открытую форму.

В репозитории нужны исходники, конфигурация Docker, Maven Wrapper, lock-файл npm и тесты. `node_modules` устанавливается командой `npm ci`; `frontend/dist` и `backend/target` создаются при сборке и не хранятся в Git.

Проверка backend из каталога `backend`: `./mvnw test` (Windows: `.\mvnw.cmd test`).
